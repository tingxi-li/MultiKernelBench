# 四个 GPU DSL 研究问题

## 已有答案、证据边界与下一步实验

**研究对象：** 性能前沿、优化迁移、TileLang 抽象层级、优化收敛

**证据等级：**

- **控制性**：`crossed_v2r3`，可支持限定范围内的结论
- **历史/描述性**：可形成假设，不能替代新的控制性实验
- **设计性**：只有实验方案，不能贡献经验结论

> 核心原则：回答“在哪个冻结实验单元中成立”，而不是直接回答“哪个 DSL 最好”。

---

# Q1｜是否有 DSL 具有更高的性能上限？

## 为什么研究 + 如何设置

**为什么重要**

- “最高跑分”会影响 DSL 选择，但容易混入幸存者偏差、调参预算和不可达实现。
- 因此把“上限”操作化为：**冻结预算内、通过正确性门控的可实现前沿**，而不是理论语言上限。

**实验设置（控制性：`crossed_v2r3`）**

- 固定一个 GEMM+bias+GELU+row-softmax 算子、RTX 6000 Ada、工具链和正确性契约。
- 完整审计 `4 策略 × 4 实现通道 × 19 网格 = 304` 个请求单元；失败仍留在分母中。
- 只让 249 个 `GATE_PASSED` 单元进入筛选；每个单元用两个全新进程。
- 机械化选择 44 个确认单元，在 15 个随机区组中比较；主估计量使用试次 60–99。
- 用逐字节相同实现的重复标签空对照，给测量分辨率设下限。

**设计理由：** 在同一策略、网格、硬件和门控内比较实现通道，才能把局部差异归因于实现，而不是不同工作或不同搜索机会。

---

# Q1｜结果、证据与还需补做的实验

## 当前答案：没有证据支持“某个 DSL 普遍拥有更高上限”

同一个 register-fused 对比在两个合法网格上发生**胜者反转**：

| Triton / TileLang | 中位时间比 | 精确区间 | 局部解释 |
|---|---:|---:|---|
| `g01` | 1.107191 | [1.094122, 1.108998] | TileLang 更快 |
| `g05` | 0.972200 | [0.956693, 0.979142] | Triton 更快 |

比值大于 1 表示分子更慢；两个区间都越过空对照分辨率下限。完整实验保留 304/304 个审计结果，28 个预注册正值对比中只有 18 个满足报告规则。

**证据支持：** 存在**单元特定的有限预算性能前沿**；不支持稳定的 DSL 排名。

**还需实验：**

- 预注册多算子、多形状、多输入分布和多架构的共同可达子集；每个 DSL 使用相等且可核查的调优预算。
- 在独立硬件/进程上重复选择与确认，并提前声明跨单元的汇总估计量。
- 当前获准的第二架构实验只有可行性审计；它能检验可达性，**不能**单独回答跨架构性能上限。

证据：[`crossed_v2r3` 结果备忘录](fused_epilogue_crossed_v2/RESULT_CROSSED_V2R3_20260802.md)

# Q2｜优化轨迹是否可以迁移？

## 为什么研究 + 应如何设置

**为什么重要**

- 如果知识可迁移，社区可以复用算法机制，而不必在每个 DSL 中从零搜索。
- “最终策略可表达”不等于“优化轨迹可迁移”：轨迹还包含顺序、前置条件、失败路径和重调优成本。

**最低限度的有效实验**

1. 冻结供体轨迹及每一步的语义机制，翻译每个前缀，而不只翻译最终内核。
2. 对每个目标 DSL 设置两种模式：逐字面迁移，以及相同预算下的受限重调优。
3. 固定输入、正确性门控、硬件、候选数和停止规则；构建失败也消耗一次尝试。
4. 用新的筛选/确认进程估计“迁移后是否保持正确，以及收益保留多少”。
5. 若要泛化到“迁移者无关”，加入相互独立的翻译者或实现者重复。

现有 `reciprocal_v2` 只给出了一个 24 单元起点：`3 个来源 × 4 个目标 × 2 种模式`。

**设计理由：** 相等的候选数不一定代表相等成本；必须同时记录编译时间、主动计算时间和失败，才能区分“机制不可迁移”与“预算不足”。

---

# Q2｜结果、证据与还需补做的实验

## 当前答案：机制可以跨通道表达；有序优化轨迹是否可迁移仍未知

**已有证据**

- `register_fused`、`global_intermediate`、`register_common_postprocess` 在四个实现通道的 15 个网格上共同可达。
- 这只证明**策略级可表达性**，没有观测同一优化步骤序列在目标 DSL 中的收益保留率。
- 历史 Phase-1 A/B/C/D 产物不能作为迁移证据：matmul-v4 中每条路径都在 512 个 `legacy_u01` 和 512 个 `opposing_means` 输入上失败。
- `reciprocal_v2` 明确标记为 **design-only and not launchable**，因此没有经验结果。

**还需实验**

- 补齐翻译源、构建/调用 ABI 和执行器，在新 campaign ID 下冻结后再运行；不得复用退役或失败实验的选择结果。
- 对每个轨迹前缀报告正确性、资源失败、绝对性能和供体收益保留率。
- 逐字面迁移作为主要因果对比；重调优结果只有在设计能识别来源效应时才升级为控制性结论。
- 该工作按现行策略推迟到当前论文之后。

证据：[`reciprocal_v2` 纠正设计](reciprocal_v2/REDESIGN_20260731.md)；[`matmul-v4` 审计](robust_gate/audits/matmul_v4_instrument_v1/results/summary.json)

# Q3｜TileLang 的较低抽象层级是否提高效率？

## 为什么研究 + 如何设置

**为什么重要**

- 较低层级可能开放手工调度能力，但也增加代码、同步错误和搜索成本。
- 必须分开三个问题：**同一算法的运行效率、表达/搜索成本、低层级是否启用新数据流**。

**历史局部匹配实验**

- 固定一个 matmul 形状、同一 TileLang 工具链、相同数值结果和相同 tensor-core MMA 工作。
- 高层 `H1`：`T.Pipelined + T.copy + T.gemm`；中层 `M2`：显式双缓冲、提交/等待与同步。
- 在两者都存在的 pipeline depth=2 上匹配比较；充分预热时钟状态，执行 L2 刷新，并使用五个进程计时。
- 预注册判定规则把 3%–10% 设为“不作结论”区间；实验测量下限约为 3.5%。

**设计理由：** pipeline 深度、tensor-core 指令和算法必须固定，否则观察到的是不同工作图或硬件路径，而不是抽象层级本身。

---

# Q3｜结果、证据与还需补做的实验

## 当前答案：匹配 matmul 中，较低层级没有表现出效率优势

| TileLang 实现 | 层级 | 时间 | 相对结果 |
|---|---|---:|---:|
| `H1@stages=2` | 高层、编译器管理 pipeline | 0.995 ms | 基线 |
| `M2` | 中层、手写双缓冲 | 1.071 ms | 慢 7.7% |

- 两者动态 MMA 数相同（33,554,432）且数值结果相同。
- 方向上高层实现更快，但 7.7% 落入预注册的 3%–10% 空档，因此**正式判定为 no verdict**。
- 表达成本也没有显示低层更简单：TileLang `prim_func` 主体为高层 18 行、`M2` 35 行；行数只是代理量，不是开发时间。
- 这是历史、单算子局部证据，尚未在当前 matmul-v4 契约内重新裁定，不能作为当前论文的控制性性能结论。

**还需实验：** 在当前门控下重跑；扩展至多算子/形状；分别做“算法固定的抽象开销”与“低层启用新数据流”的实验；若研究搜索效率，则随机化起始层级并记录开发时间、编译次数和失败次数。

证据：[`Phase-1 TileLang abstraction study`](../phase1_matmul/PHASE1_REPORT.md)

# Q4｜简单内核是否比复杂内核更快收敛？

## 为什么研究 + 应如何设置

**为什么重要**

- 它决定基准搜索预算、自动调优停止规则和 DSL 易用性评价。
- 但“简单”和“收敛”必须先定义；否则候选编号、墙钟时间和最终最好点都会给出不同答案。

**建议的控制性设计**

- 事前用独立决策轴定义复杂度，例如数据流、布局、tile、pipeline、精度和融合选择数。
- 主要终点：首次找到“通过门控且进入冻结参考前沿 5% 内”的候选所需尝试数；失败作为竞争事件保留，预算耗尽作为删失保留。
- 对所有算子固定搜索者、提示、先验信息、候选预算、硬件和正确性门控，并运行多个独立种子。
- 同时报告候选数、token、编译时间、主动 GPU 时间和墙钟时间。

**设计理由：** 慢参考实现、编译缓存、初始答案质量和人工提示都会改变墙钟时间；只有在这些因素平衡后，才能把差异归因于内核复杂度。

---

# Q4｜结果、证据与还需补做的实验

## 当前答案：历史轨迹显示趋势，但没有控制性证据证明因果关系

| 历史算子类别 | 首次进入最终最好点 5% 内的平均自定义迭代 |
|---|---:|
| Sum reduction | 1.0 |
| LayerNorm（有提示） | 1.5 |
| Depthwise convolution | 1.5 |
| Fused matmul | 1.75 |
| SDPA | 3.0 |
| Standard matmul | 4.75 |

**为什么还不能下结论**

- 提示、搜索路径、失败率和每次候选成本并未随机化或平衡；墙钟时间也不随复杂度单调变化。
- “最终最好点”由同一条有限轨迹定义，可能把过早停止误写成收敛。
- `convergence_v2` 在启动前已经退役，192 行核心 manifest 没有产生经验数据。

**还需实验：** 使用新 campaign ID 和预注册终点；按复杂度分层抽样算子；在相同搜索协议下运行独立重复；用失败感知的 time-to-event 分析，并通过前瞻性功效分析决定重复数。

证据：[`历史跨 DSL 报告`](../CONTROLLED_CROSS_DSL_REPORT.md)；[`convergence_v2` 退役说明](convergence_v2/RETIREMENT_20260731.md)

# 总结｜目前可以说到哪里？

| 问题 | 最强的当前答案 | 证据等级 |
|---|---|---|
| 某个 DSL 有更高性能上限？ | 只存在单元特定前沿；没有通用胜者证据 | 控制性、但仅限 Ada 局部单元 |
| 优化轨迹可迁移？ | 策略可跨通道表达；有序轨迹迁移未知 | 设计性，未执行 |
| TileLang 低层级更高效？ | 匹配 matmul 未显示低层运行优势 | 历史、局部、正式 no verdict |
| 简单内核收敛更快？ | 有描述性趋势，没有因果结论 | 历史描述；控制实验已退役 |

## 对社区最可复用的认识

1. 把可表达性、可行性、正确性、性能和搜索成本作为不同终点。
2. 公布完整请求分母；失败不是应从性能表中消失的样本。
3. 只在共同可达、因素隔离、全新确认且越过空对照分辨率的单元上报告性能。
4. 对未执行的设计和历史趋势，最严谨的答案就是：**尚未知道，以及下一项能识别它的实验是什么。**
